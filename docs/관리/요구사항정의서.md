# 요구사항 정의서

StockCast — NFC와 공공데이터로 돌아가는 공공조달 재고관리 백오피스
김연동 / 2026-09-03 기준 / v2.0

v1.0(2026-06-03)에는 기능 8건, 데이터 4건이 있었다. 2차 확장으로 설비 유지보수와
운영 관리, 챗봇이 붙으면서 항목이 많이 늘어 다시 정리했다. 원본은
[제출산출물/김연동_StockCast_20260603.xlsx](../제출산출물/김연동_StockCast_20260603.xlsx)에 있다.

## 1. 개요

### 무슨 업무인가

공공조달 납품업체의 내부 운영이다. 고객이 보는 화면은 없다. 재고·조달·수요예측·
설비·경영분석 같은 관리 업무만 다룬다.

### 누가 쓰나

| 역할 | 관심사 | 주로 보는 화면 |
|:---|:---|:---|
| 창고 담당자 | 빨리 기록하고, 물건 떨어지지 않게 | NFC 입출고 |
| 재고 관리자 | 언제 얼마나 발주할지, 재고가 남거나 모자라지 않게 | KPI 대시보드, 발주 권고 |
| 설비 담당자 | 설비 고장 예방, 정비 이력 | 설비 유지보수 |
| 경영진 | 운전자본, 회전율, 어디에 집중할지 | KPI 대시보드, AI 요약 |
| 시스템 운영자 | 서비스가 살아 있는지, 데이터를 믿을 수 있는지 | 운영 관리 |

### 범위

들어가는 것: 재고관리(SAP MM 구조), NFC 입출고, 공공데이터 수집, 수요예측,
안전재고·발주, 경영 KPI, Odoo 양방향 연동, 설비 유지보수, 시스템 운영 관리.

빠지는 것: 회계·전표, 인사, 고객 주문(B2C), 배송 추적, 멀티테넌트.

| FR-02 | SAP MM 기반 재고관리 | 자재마스터와 저장위치별 재고를 SAP MM 구조로 관리한다 | 상 | `material` `stock` `storage_location` | ● |
| FR-03 | 자재문서 전기 | 모든 입출고를 자재문서로 기록하고, 재고는 이동방향×수량의 결과로 갱신한다 | 상 | `material_doc_header` `material_doc_item` | ● |
| FR-04 | 외부 공공데이터 수집 | 기상청 날씨, 공휴일, 나라장터 입찰, 조달청 단가를 수집해 넣는다 | 중 | `ext_*` | ● |

| FR-06 | 수요 예측 (시계열) | 외부변수 없이 추세와 요일 계절성으로 앞을 내다본다 (Holt-Winters / SARIMA) | 중 | `material_doc_item` | ● |
| FR-07 | 안전재고·재주문점 산출 | `SS=Z·σ·√L`, `ROP=d̄·L+SS`, 발주상한을 계산해 발주 시점과 수량을 제시한다 | 상 | `stock` | ● |
| FR-08 | 재고 이력 관리 | 월말 재고를 스냅샷으로 쌓아 평균재고·회전율·결품률의 근거로 쓴다 | 중 | `stock_snapshot_history` | ● |

| FR-10 | ABC 분석 | 매출 파레토로 A/B/C 등급을 나눠 관리 강도를 차등한다 | 중 | `material` `material_doc_item` | ● |
| FR-11 | AI 운영요약 | 운영현황·수요회전·재고건전성·ABC·권장조치를 근거와 함께 서술한다 | 하 | — | ● |

## 4. 비기능 요구사항

| ID | 구분 | 요구사항 | 어떻게 확인하나 | |
|:---|:---|:---|:---|:---:|
| NFR-01 | 가용성 | 외부 API 키가 없거나 장애여도 재고·분석·화면은 동작한다 | 커넥터별 rollback 후 계속, 키 없으면 건너뜀 | ● |
| NFR-02 | 가용성 | LLM이 없거나 실패해도 AI 요약과 챗봇이 답한다 | 규칙 기반 폴백, 테스트로 고정 | ● |
| NFR-03 | 가용성 | Odoo가 끊겨도 분석 기능은 정상 동작한다 | `degraded` 상태로 구분, graceful 응답 | ● |
| NFR-04 | 무결성 | 재고보다 많은 출고는 거부한다 | 409 Conflict, 테스트로 고정 | ● |
| NFR-05 | 무결성 | 외부 데이터 수집은 여러 번 돌려도 중복되지 않는다 | `merge` upsert | ● |
| NFR-06 | 보안 | 비밀값이 저장소에 올라가지 않는다 | `.env`·`tfvars`·`tfstate` gitignore, 코드는 settings로만 접근 | ● |
| NFR-07 | 보안 | 운영 접속은 HTTPS만, SSH는 지정 IP만 | Caddy + 보안그룹 | ● |
| NFR-08 | 보안 | 챗봇에 DB 접근 권한을 주지 않는다 | 서버가 조회한 수치만 넘긴다 | ● |
| NFR-09 | 이식성 | 로컬과 운영이 같은 방식으로 뜬다 | 동일한 `docker compose` | ● |
| NFR-10 | 이식성 | 테스트가 외부 DB나 키 없이 돌아간다 | SQLite 인메모리 + `conftest.py` 고정 | ● |
| NFR-11 | 재현성 | 인프라를 코드로 다시 만들 수 있다 | Terraform | ● |
| NFR-12 | 관측성 | 운영자가 SSH 없이 상태·로그·정합성을 본다 | `/api/ops/*` + 운영 화면 | ● |
| NFR-13 | 품질 | 주요 로직이 자동 테스트로 보호된다 | pytest 75건, CI에서 자동 실행 | ● |
| NFR-14 | 유지보수성 | 설계 문서가 코드와 어긋나지 않는다 | ERD·명세서를 ORM에서 생성(`gen_docs.py`), CI에서 드리프트 검사 | ● |
| NFR-15 | 사용성 | 비전공자도 화면의 경영용어를 이해한다 | `?` 툴팁 + 용어집 35개 | ● |
| NFR-16 | 확장성 | LLM 공급자를 코드 수정 없이 바꾼다 | provider 추상화, `.env`만 변경 | ● |
| NFR-17 | 가용성 | 장애나 공격으로 서버가 죽어도 자동 복구된다 | 헬스체크→재기동, 백업 복구, 침입 차단 | ○ |
| NFR-18 | 가용성 | DB를 관리형으로 분리해 백업·복구를 맡긴다 | AWS RDS 전환 | ○ |
| NFR-19 | 보안 | 운영 API를 권한으로 보호한다 | RBAC | ○ |

## 5. 제약사항

| 구분 | 제약 | 어떻게 대응했나 |
|:---|:---|:---|
| 비용 | AWS 프리티어 범위를 지향, 유료 SaaS 불가 | EC2 한 대 + Odoo Community(LGPL) + 무료 DuckDNS |
| 데이터 | 실 판매 트랜잭션을 구할 수 없음 | 실제 날씨·휴일·단가를 입력으로 쓰는 시뮬레이션 |
| API | 조달청 입찰 API 조회기간이 한 달로 제한 | 최근 30일만 수집 |
| API | Odoo 온라인 무료판이 XML-RPC 차단 | Docker 자체 호스팅 |
| 하드웨어 | Web NFC는 안드로이드 크롬 + HTTPS에서만 동작 | HTTPS 적용, iOS는 등록 태그 클릭으로 대체 |
| 학사 | 단일 기업 백오피스에 집중 | `tenant_id` 미도입 |
