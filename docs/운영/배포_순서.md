# 배포 순서

한 번에 다 되지 않는다. 순서를 지켜야 하는 이유가 각 단계에 있다.
`terraform apply` 는 5번이고, 그 앞은 준비, 뒤는 확인이다.

## 배포 전

### 1. SSH 키페어

인스턴스를 만들 때 이름으로 참조하므로 **미리 있어야 한다.** 없으면 apply 가 실패한다.

```bash
aws ec2 describe-key-pairs --region ap-northeast-2 --key-names stockcast-key
```

없으면 만든다. 개인키는 AWS 가 딱 한 번만 보여주므로 바로 저장해야 한다.

```bash
aws ec2 create-key-pair --region ap-northeast-2 \
  --key-name stockcast-key --key-type ed25519 \
  --query KeyMaterial --output text > ~/.ssh/stockcast-key.pem
chmod 600 ~/.ssh/stockcast-key.pem
```

`terraform.tfvars` 의 `key_pair_name` 과 이름이 같아야 한다.

### 2. 내 공인 IP

SSH·8000·8069 를 내 IP 로만 열어 뒀다. IP 가 바뀌면 접속이 막힌다.
집·학교·카페가 다르고, 통신사에 따라 며칠 만에도 바뀐다.

```bash
curl -s https://checkip.amazonaws.com
# 나온 값을 tfvars 의 my_ip 에 "x.x.x.x/32" 형태로 넣는다
```

### 3. 비밀값을 SSM 에 넣기

`use_ssm = true` 로 쓸 때만 해당된다. **apply 보다 먼저** 해야 한다.
terraform 이 RDS 비밀번호를 SSM 에서 읽어 오기 때문에, 값이 없으면 apply 가 멈춘다.

```bash
./scripts/put_secrets.sh          # 무엇이 올라갈지 먼저 본다
./scripts/put_secrets.sh --apply
./scripts/put_secrets.sh --list   # 들어갔는지 확인
```

DB 비밀번호는 `.env` 의 개발용 값을 그대로 쓰지 말 것. 따로 강한 값을 넣는다.

```bash
NEWPW=$(LC_ALL=C tr -dc 'A-Za-z0-9' </dev/urandom | head -c 28)
aws ssm put-parameter --region ap-northeast-2 --name /stockcast/db_password \
  --type SecureString --value "$NEWPW" --overwrite
unset NEWPW
```

넣었으면 `tfvars` 에서 `db_password`·`gemini_api_key`·`kma_api_key`·`holiday_api_key`
네 줄을 지우거나 주석 처리한다. 남겨 두면 tfstate 에 평문으로 들어가서 옮긴 의미가 없다.

### 4. (선택) 원격 상태

지금은 상태가 로컬 파일 하나다. 혼자 쓰면 당장은 굴러가지만, 파일을 잃으면
terraform 이 기존 리소스를 모른다. 옮길 거면 **apply 전에** 하는 게 깔끔하다.

```bash
cd infra/terraform-bootstrap && terraform init && terraform apply
terraform output backend_config       # 나온 내용을 backend.tf 로 저장
cd ../terraform && terraform init -migrate-state
```

## 배포

### 5. apply

무엇이 생기는지 먼저 본다. **0 to destroy** 인지 반드시 확인한다.

```bash
make tf-plan
cd infra/terraform && terraform apply
```

리소스 14개가 생긴다. RDS 가 5~10분 걸려서 전체가 10분 정도다.

| 종류 | 개수 |
|---|---:|
| EC2·EIP·보안그룹(앱) | 3 |
| RDS·서브넷그룹·보안그룹(DB) | 3 |
| IAM 역할·정책·인스턴스 프로파일 | 3 |
| CloudWatch 알람 | 2 |
| SNS 주제·구독 | 2 |
| 예산 | 1 |

## 배포 후

### 6. DuckDNS 주소 갱신

EIP 가 새로 생겨서 도메인이 아직 옛 주소를 가리킨다. **HTTPS 보다 먼저** 해야 한다.
Caddy 가 인증서를 받으려면 도메인이 이 서버를 가리켜야 하기 때문이다.

```bash
terraform -chdir=infra/terraform output -raw public_ip
curl "https://www.duckdns.org/update?domains=<도메인앞부분>&token=<토큰>&ip=<새IP>"
dig +short <도메인>.duckdns.org      # 바뀌었는지 확인
```

토큰을 `.env` 의 `DUCKDNS_TOKEN` 에 넣어 두면 다음부터는
`make aws-start` 가 알아서 갱신한다.

### 7. 부팅이 제대로 됐는지

`user_data` 는 인스턴스를 처음 만들 때 한 번만 돈다. 여기서 실패하면 조용히 넘어간다.

```bash
ssh -i ~/.ssh/stockcast-key.pem ec2-user@<새IP>

sudo tail -50 /var/log/stockcast-userdata.log   # 어디까지 갔나
free -h                                          # 스왑 2GB 붙었나
cat /etc/stockcast.env                           # COMPOSE_FILES 에 rds.yml 있나
systemctl status stockcast                       # 서비스가 떴나
make ps
```

`.env` 에 비밀값이 들어갔는지도 본다(값은 보지 말고 비어 있지 않은지만).

```bash
sudo grep -c '^GEMINI_API_KEY=.\+' /opt/stockcast/.env
```

### 8. 헬스체크

```bash
curl -s localhost:8000/api/ops/health    | python3 -m json.tool
curl -s localhost:8000/api/ops/integrity | python3 -m json.tool
```

`database.ok` 가 true 여야 RDS 에 제대로 붙은 것이다.
`odoo` 는 아직 false 가 정상이다(9번에서 띄운다).

### 9. Odoo

Odoo 는 컨테이너 볼륨이 비어 있어서 DB 를 새로 만들어야 한다. 이건 화면에서 해야 한다.

```bash
cd /opt/stockcast/infra/odoo && docker compose -f docker-compose.odoo.yml up -d
```

브라우저로 `http://<새IP>:8069` 에 들어가 DB 생성 마법사를 돌린다.
DB 이름은 `.env` 의 `ODOO_DB` 와 같아야 한다(`stockcast`).
재고관리 앱을 설치한 뒤 적재한다.

```bash
cd /opt/stockcast
make seed                                                   # 비어 있으면 시드
docker compose $COMPOSE_FILES exec -T backend python /workspace/scripts/odoo_ping.py
docker compose $COMPOSE_FILES exec -T backend python /workspace/scripts/odoo_load.py
docker compose $COMPOSE_FILES exec -T backend python /workspace/scripts/odoo_sync_reorder.py
```

### 10. HTTPS

도메인이 이 서버를 가리키는 걸 6번에서 확인한 뒤에 띄운다.
안 그러면 Let's Encrypt 발급이 실패하고, 짧은 시간에 여러 번 실패하면 한도에 걸린다.

```bash
cd /opt/stockcast/infra/caddy && docker compose -f docker-compose.caddy.yml up -d
docker compose -f docker-compose.caddy.yml logs --tail=30   # 인증서 발급 확인
curl -I https://<도메인>.duckdns.org
```

### 11. 자동 복구가 도는지

```bash
systemctl list-timers stockcast-watchdog.timer
sudo tail -20 /var/log/stockcast-watchdog.log
```

한 번 일부러 죽여 본다. 2분 안에 살아나야 한다.

```bash
docker pause erp_nfc_backend      # 재시작 정책으로는 안 풀리는 고장
# 2분 기다린 뒤
curl -s localhost:8000/health
```

### 12. 알람

SNS 구독은 **메일의 확인 링크를 눌러야** 시작된다. 안 누르면 알람이 와도 메일이 안 온다.

```bash
aws sns list-subscriptions-by-topic --region ap-northeast-2 \
  --topic-arn $(aws sns list-topics --region ap-northeast-2 \
    --query "Topics[?contains(TopicArn,'stockcast')].TopicArn" --output text)
# SubscriptionArn 이 PendingConfirmation 이면 아직 안 누른 것이다

aws cloudwatch describe-alarms --region ap-northeast-2 \
  --alarm-name-prefix stockcast --query 'MetricAlarms[].[AlarmName,StateValue]' --output table
```

`INSUFFICIENT_DATA` 로 시작해서 몇 분 뒤 `OK` 로 바뀐다.

### 13. 배포 파이프라인

`deploy.yml` 이 옛 IP 를 보고 있다. 저장소 Settings → Secrets 에서 바꾼다.

- `EC2_HOST` → 새 EIP
- `EC2_SSH_KEY` → `~/.ssh/stockcast-key.pem` 내용 전체

### 14. 백업 걸기

```bash
sudo mkdir -p /opt/backup
cd /opt/stockcast && ./scripts/backup.sh --verify    # 한 번 손으로 돌려 본다
(crontab -l 2>/dev/null; echo "0 3 * * * cd /opt/stockcast && ./scripts/backup.sh >> /var/log/stockcast-backup.log 2>&1") | crontab -
```

RDS 자동 백업(7일)이 이미 돌지만, 파일로도 갖고 있는 편이 낫다.
스냅샷은 계정을 잃으면 같이 잃는다.

### 15. 비용 확인

```bash
make aws-status     # 상태와 이번 달 비용
```

24시간 켜 두면 월 $41.52 다. 안 쓸 때는 내린다.

```bash
make aws-stop       # 하루 8시간이면 월 $16.78
```

예산 알람은 $50 기준으로 80% 도달 시 메일이 온다.

## 되돌리기

```bash
cd infra/terraform
terraform destroy
```

RDS 는 `deletion_protection = true` 라 바로 안 지워진다.
지우려면 `db_deletion_protection = false` 로 바꿔 apply 를 먼저 한 뒤 destroy 한다.
일부러 그렇게 해 뒀다. 실수로 DB 를 날리는 게 제일 무섭다.

키페어와 SSM 파라미터는 terraform 이 만들지 않았으므로 따로 지운다.

```bash
aws ec2 delete-key-pair --region ap-northeast-2 --key-name stockcast-key
aws ssm delete-parameters --region ap-northeast-2 \
  --names /stockcast/db_password /stockcast/gemini_api_key \
          /stockcast/kma_api_key /stockcast/holiday_api_key
```
